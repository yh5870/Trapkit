# PRD: Tripkit — AI 여행 준비물 리스트 & 수화물 규정 체크 서비스

## 1. 제품 개요

**챙김**은 여행자가 목적지와 여행 목적을 입력하면 AI가 **맞춤 준비물 체크리스트**를 생성해주고, 해당 목적지의 **여행 주의사항**과 **항공 수화물 규정**까지 함께 안내해주는 여행 준비 도우미 서비스이다.

기존 준비물 체크리스트 앱은 대부분 미리 만들어진 고정 템플릿(국내여행/해외여행/캠핑 등)을 제공한다. 하지만 실제 준비물은 **어디로, 왜, 언제, 며칠** 가는지에 따라 크게 달라진다. 겨울 삿포로 스키 여행과 여름 다낭 휴양 여행의 준비물은 완전히 다르고, 출장과 배낭여행의 준비물도 다르다.

챙김은 AI를 활용해 여행 맥락에 맞는 체크리스트를 생성하되, 사용자가 자유롭게 **추가·수정·삭제**할 수 있게 하고, 계정에 저장해 여행 준비 기간 내내 관리할 수 있게 한다. 특히 해외여행에서 가장 헷갈리는 **기내 반입/위탁 수화물 규정**은 별도의 체커 페이지로 제공하여, 제품명과 용량만 입력하면 반입 가능 여부를 즉시 확인할 수 있게 한다.

## 2. 문제 정의

### 2.1 사용자가 겪는 문제

여행을 준비할 때 사용자는 보통 다음과 같이 행동한다.

* 메모 앱에 준비물을 생각나는 대로 적는다.
* "○○ 여행 준비물" 블로그 글을 검색해서 짜깁기한다.
* 체크리스트 앱의 고정 템플릿을 받아서 필요 없는 항목을 지운다.
* 수화물 규정은 항공사 홈페이지나 커뮤니티 글을 뒤진다.

이 방식에는 다음과 같은 아쉬움이 있다.

1. **내 여행에 맞는 리스트가 아니다.**
   템플릿은 목적지의 기후, 여행 목적, 계절을 반영하지 못한다. 결국 사용자가 직접 걸러내야 한다.

2. **빠뜨리는 항목이 생긴다.**
   목적지 특화 항목(돼지코 어댑터, 특정 국가 비자 서류, 우기용 우비 등)은 경험이 없으면 떠올리기 어렵다.

3. **수화물 규정 확인이 번거롭다.**
   "선크림 150ml 기내 반입 되나요?" 같은 질문이 커뮤니티에 반복해서 올라온다. 액체류 100ml 규정, 보조배터리 위탁 금지, 라이터 규정 등은 항목마다 흩어져 있어 한 번에 확인하기 어렵다.

4. **목적지별 주의사항을 따로 찾아야 한다.**
   팁 문화, 치안, 물 위생, 전압, 출입국 규정 등은 준비물과 별개로 검색해야 한다.

5. **준비 상황이 흩어져서 관리된다.**
   리스트는 메모 앱에, 규정은 브라우저 북마크에, 메모는 카톡 "나에게 보내기"에 흩어진다.

## 3. 제품 목표

### 3.1 핵심 목표

챙김의 핵심 목표는 다음과 같다.

* 목적지와 여행 목적을 입력하면 AI가 맞춤 준비물 체크리스트를 생성한다.
* 생성된 리스트를 사용자가 자유롭게 추가·수정·삭제하고 체크할 수 있게 한다.
* 목적지 기준 여행 주의사항과 수화물 규정 요약을 함께 제공한다.
* 제품명과 용량을 입력하면 기내 반입/위탁 가능 여부를 판정하는 수화물 체커를 별도 페이지로 제공한다.
* 회원가입/로그인을 지원하고, 계정별로 여행(체크리스트)과 메모를 저장한다.

### 3.2 비목표

초기 버전에서는 다음 기능을 제공하지 않는다.

* 항공권/숙소 예약 및 가격 비교
* 실시간 항공편 조회
* 상세 여행 일정(itinerary) 짜기 — 준비물 중심으로 시작한다
* 여행 경비 정산 / 가계부
* 여러 명이 하나의 리스트를 함께 편집하는 공유 기능 (2차 버전)
* 소셜 기능 (팔로우, 피드)

초기 제품은 **개인 여행자의 준비 단계**에 집중한다.

## 4. 핵심 가치 제안

### 4.1 한 줄 설명

**"검색하고 짜깁기하는 여행 준비를, 입력 한 번으로 끝내주는 서비스."**

### 4.2 사용자에게 주는 가치

* 블로그를 여러 개 뒤질 필요 없이 내 여행에 맞는 리스트를 바로 받는다.
* 놓치기 쉬운 목적지 특화 준비물(어댑터, 서류, 계절 용품)을 AI가 먼저 챙겨준다.
* "이거 기내 반입 되나?"를 커뮤니티에 묻지 않고 즉시 확인한다.
* 준비물, 주의사항, 규정, 메모가 한 계정 안에서 관리된다.
* 다음 여행 때 지난 리스트를 복사해서 다시 쓸 수 있다.

## 5. 타깃 사용자

### 5.1 1차 타깃

해외여행을 준비하는 20~30대 자유여행자

특징:

* 패키지보다 자유여행을 선호한다.
* 여행 전 블로그/유튜브로 정보를 많이 검색한다.
* 저비용항공사(LCC)를 자주 이용해 수화물 규정에 민감하다.
* 체크리스트를 만들지만 매번 처음부터 다시 만든다.

### 5.2 2차 타깃

출장이 잦은 직장인

특징:

* 짧은 일정으로 자주 이동한다.
* 준비물이 패턴화되어 있어 리스트 재사용 가치가 높다.
* 기내 반입만으로 다니는 경우가 많아 액체류 규정을 자주 확인한다.

### 5.3 3차 타깃

가족 단위 여행자

특징:

* 인원이 많아 준비물 수가 많고 누락 리스크가 크다.
* 유아용품, 의약품 등 규정 확인이 필요한 품목이 많다.
* 체크리스트를 역할 분담용으로 쓰고 싶어 한다. (공유 기능 — 2차 버전 수요)

## 6. 사용자 시나리오

### 6.1 기본 시나리오 — 리스트 생성

사용자는 12월에 삿포로로 스키 여행을 간다.

1. 홈 화면에서 목적지에 "일본 삿포로"를 입력한다.
2. 여행 목적에 "스키/스노보드"를 선택하거나 직접 입력한다.
3. (선택) 여행 기간과 출발 시기를 입력한다.
4. [리스트 만들기] 버튼을 누른다.
5. 서비스는 AI를 호출해 다음을 한 번에 보여준다.

```text
삿포로 스키 여행 준비물 (12월, 4박 5일)

[필수]
□ 여권 (유효기간 6개월 이상 확인)
□ 스키복 / 방한 내의
□ 방수 장갑, 고글
□ 돼지코 어댑터 (일본 A타입, 110V)

[의류]
□ 히트텍 상하의 3벌
□ 두꺼운 양말 5켤레
...

[주의사항 요약]
- 12월 삿포로는 평균 -4℃, 폭설로 항공편이 지연될 수 있습니다.
- 대부분 상점에서 카드 사용이 가능하지만 소규모 식당은 현금이 필요합니다.

[수화물 규정 요약]
- 스키 장비는 대부분 항공사에서 위탁 수화물로 처리되며 추가 요금이 있을 수 있습니다.
- 핫팩(철분 발열체)은 기내 반입 가능하지만 대량 반입은 제한될 수 있습니다.
```

6. 사용자는 리스트에서 필요 없는 항목을 삭제하고, "콘택트렌즈 세척액"을 직접 추가한다.
7. 로그인 상태라면 리스트가 계정에 자동 저장된다.

---

### 6.2 수화물 체커 시나리오

사용자는 선크림을 기내에 들고 탈 수 있는지 궁금하다.

1. 수화물 체커 페이지로 이동한다.
2. 제품명에 "선크림", 용량에 "150ml"를 입력한다.
3. 서비스는 판정 결과를 보여준다.

```text
선크림 150ml

기내 반입: 불가 ✕
위탁 수화물: 가능 ○

이유
액체류는 개별 용기 100ml 이하만 기내 반입할 수 있습니다.
150ml 용기는 내용물이 절반만 남았더라도 반입할 수 없습니다.

대안
- 100ml 이하 용기에 소분하면 기내 반입이 가능합니다.
- 소분 용기들은 1L 이하 투명 지퍼백 1개에 담아야 합니다.
```

4. 사용자는 이어서 "보조배터리 20000mAh"를 검색한다.

```text
보조배터리 20000mAh (약 74Wh)

기내 반입: 가능 ○
위탁 수화물: 불가 ✕

이유
리튬이온 배터리는 화재 위험 때문에 위탁 수화물에 넣을 수 없습니다.
100Wh 이하는 기내 반입이 가능합니다. (100~160Wh는 항공사 승인 필요, 통상 2개까지)
```

---

### 6.3 계정/메모 시나리오

사용자는 지난달 만든 오사카 여행 리스트를 이어서 관리한다.

1. 로그인한다.
2. 내 여행 목록에서 "오사카 벚꽃 여행"을 연다.
3. 체크리스트에서 준비 완료한 항목을 체크한다. (진행률 12/23)
4. 메모 탭에 "간사이공항 → 난바 라피트 예약 완료, QR 캡처해둠"을 적는다.
5. 메모와 체크 상태는 계정에 저장되어 어느 기기에서든 이어서 볼 수 있다.

---

### 6.4 비로그인 시나리오

1. 비로그인 사용자도 리스트 생성과 수화물 체커를 사용할 수 있다.
2. 생성 결과는 브라우저(로컬)에만 임시 보관된다.
3. 저장/메모를 시도하면 로그인을 유도한다.

```text
리스트를 저장하려면 로그인이 필요합니다.
지금 만든 리스트는 로그인 후 그대로 저장됩니다.
```

4. 로그인/가입 완료 시 임시 리스트를 계정으로 이관한다.

## 7. 주요 기능

## 7.1 여행 정보 입력 (홈)

### 기능 설명

사용자는 홈 화면에서 여행 정보를 입력해 AI 리스트 생성을 요청한다.

### 상세 요구사항

* 목적지 입력 (자유 텍스트, 예: "일본 삿포로", "다낭", "제주도")
* 여행 목적 입력 (프리셋 칩 + 자유 입력)
  * 프리셋 예시: 휴양, 관광, 스키, 서핑/수영, 트레킹, 출장, 배낭여행, 가족여행, 촬영
* (선택) 여행 기간 입력 (박수 또는 날짜 범위)
* (선택) 출발 시기 입력 (월 단위면 충분 — 계절/기후 반영용)
* (선택) 동행 유형 (혼자 / 커플 / 친구 / 가족·유아 동반)
* 최근 생성한 여행 표시 (로그인 시)

### 입력 예시

```text
목적지: 다낭
목적: 휴양, 수영
기간: 3박 4일
출발: 7월
동행: 가족 (유아 1명)
```

### 예외 처리

* 목적지가 실존하지 않거나 모호한 경우 (예: "바다"), AI 응답 단계에서 확인 질문 대신 일반 여행 기준으로 생성하고 안내 문구를 표시한다.

```text
목적지를 구체적으로 입력하면 (예: "베트남 다낭") 더 정확한 리스트를 받을 수 있어요.
```

* 목적지만 입력하고 목적을 비워도 생성 가능 (일반 관광 기준으로 생성)

## 7.2 AI 준비물 리스트 생성

### 기능 설명

입력된 여행 정보를 바탕으로 AI API를 호출해 카테고리화된 준비물 체크리스트를 생성한다.

### 상세 요구사항

* 카테고리 구분: 필수(서류/귀중품), 의류, 세면/위생, 전자기기, 의약품, 목적지 특화, 목적별 특화
* 항목별 구성: 이름, 수량(선택), 짧은 이유/팁(선택), 카테고리
* 목적지 특화 항목 반드시 포함 (전압/플러그 타입, 기후 대응, 현지 관습 대응)
* 여행 목적 특화 항목 반드시 포함 (스키 → 장비/방한, 휴양 → 수영복/방수팩 등)
* 유아 동반 시 유아용품 카테고리 추가
* 생성 결과는 항상 **구조화된 JSON**으로 받아 UI 리스트로 렌더링 (8장 참고)
* 생성 시간 동안 스켈레톤/로딩 상태 표시, 평균 응답 목표 10초 이내
* [다시 생성] 버튼 제공 (동일 입력 재생성)

### 표시 예시

```text
다낭 가족 휴양 준비물 (7월, 3박 4일)

필수
□ 여권 (전 인원, 유효기간 6개월 이상)
□ 항공권 e-티켓
□ 여행자보험 증서

목적지 특화
□ 돼지코 어댑터 (베트남 A/C타입, 220V — 한국 플러그 대부분 그대로 사용 가능)
□ 모기 기피제 (뎅기열 유행 지역)
□ 우비/우산 (7월은 우기)

유아용품
□ 기저귀 (현지 구매 가능하지만 첫날 분량은 필수)
□ 유아용 자외선차단제
...
```

## 7.3 체크리스트 편집

### 기능 설명

AI가 생성한 리스트는 시작점일 뿐이며, 사용자가 완전히 통제할 수 있어야 한다.

### 상세 요구사항

* 항목 체크 / 체크 해제
* 항목 추가 (카테고리 선택 + 이름 입력, 인라인 입력)
* 항목 수정 (이름, 수량, 메모)
* 항목 삭제 (스와이프 또는 삭제 버튼, 실행 취소 지원)
* 카테고리 추가/이름 변경
* 항목 순서 변경 (드래그 앤 드롭)
* 전체 진행률 표시 (예: 12/23 · 52%)
* 체크 완료 항목 접기/펼치기
* AI 생성 항목과 사용자 추가 항목 구분 표시 (source 필드)

### 편집 동작 원칙

* 모든 편집은 즉시 저장된다. (로그인: 서버 / 비로그인: 로컬)
* AI [다시 생성] 시 사용자가 추가/수정한 항목은 유지하고, AI 생성 항목만 교체할지 전체 교체할지 선택하게 한다.

```text
다시 생성하면 기존 리스트가 바뀝니다.

( ) 내가 추가·수정한 항목은 유지하고 나머지만 새로 받기
( ) 전체 새로 받기
```

## 7.6 수화물 체커 (별도 페이지)

### 기능 설명

제품명과 용량/사양을 입력하면 기내 반입/위탁 가능 여부를 판정해주는 독립 페이지. 서비스의 차별화 핵심 기능이다.

### 상세 요구사항

* 입력: 제품명 (자유 텍스트) + 용량/수치 (선택: ml, g, mAh, Wh, cm)
* 출력: 기내 반입 (가능/조건부/불가) + 위탁 수화물 (가능/조건부/불가) + 이유 + 대안/팁
* 판정 3단계 표기: ○ 가능 / △ 조건부 가능 / ✕ 불가
* 자주 찾는 품목 바로가기 칩 제공 (보조배터리, 선크림, 라이터, 전자담배, 향수, 헤어스프레이, 손톱깎이, 상비약, 유아 이유식, 노트북)
* 검색 이력 표시 (로그인 시 계정 저장, 비로그인 시 로컬)
* 판정 방식: **정적 규칙 DB 우선 + AI 보조** (15장 참고)
  * 규칙 DB에 있는 품목은 DB 기준으로 즉시 판정 (일관성·정확성 보장)
  * DB에 없는 품목은 AI 판정 + "AI 판정" 라벨 표시
* 국제선/국내선 구분 토글 (기본: 국제선)

### 판정 예시

```text
입력: 헤어스프레이 300ml

기내 반입: 불가 ✕   (액체·에어로졸 100ml 초과)
위탁 수화물: 조건부 가능 △   (개당 500ml 이하, 총 2L 이하의 인화성 없는 생활용 에어로졸)

팁: 여행용 미니 사이즈(100ml 이하)를 구매하면 기내 반입이 가능합니다.
```

### 고지 문구 (페이지 하단 고정)

```text
본 판정은 국토교통부 고시 및 일반적인 국제 기준(IATA)을 바탕으로 한 참고 정보입니다.
항공사·출발 국가에 따라 세부 규정이 다를 수 있으니, 최종 확인은 이용 항공사 안내를 따르세요.
```

## 8. AI 리스트 생성 설계

## 8.1 기본 아이디어

AI 호출은 자유 텍스트가 아니라 **구조화된 JSON 응답**을 강제한다. 프론트는 JSON을 그대로 체크리스트 UI로 렌더링하고, 항목 단위 편집(추가/수정/삭제)이 가능해야 하기 때문이다.

호출은 항상 **서버(백엔드)에서만** 수행한다. AI API 키는 서버 환경변수로 관리하며 클라이언트에 절대 노출하지 않는다.

---

## 8.2 요청 프롬프트 구성

### 시스템 프롬프트 요지

```text
너는 여행 준비물 전문가다. 아래 여행 정보를 바탕으로 준비물 체크리스트,
여행지 주의사항, 수화물 규정 요약을 JSON으로만 응답한다.
- 마크다운, 설명 문장 없이 JSON만 출력한다.
- 목적지의 기후(출발 월 기준), 전압/플러그, 관습을 반드시 반영한다.
- 여행 목적에 특화된 항목을 반드시 포함한다.
- 수화물 규정 요약에는 생성한 준비물 중 규정 이슈가 있는 항목만 담는다.
- 확실하지 않은 시의성 정보(비자 등)는 confidence: "check_required"로 표시한다.
```

### 사용자 프롬프트 예시

```json
{
  "destination": "일본 삿포로",
  "purpose": ["스키"],
  "duration_nights": 4,
  "departure_month": 12,
  "companions": "친구 2명"
}
```

## 8.3 응답 JSON 스키마

```json
{
  "trip_title": "삿포로 스키 여행",
  "categories": [
    {
      "name": "필수",
      "items": [
        {
          "name": "여권",
          "quantity": null,
          "tip": "유효기간 6개월 이상 확인",
          "baggage_flag": null
        },
        {
          "name": "보조배터리",
          "quantity": "1개",

    },

    }
  ]

```

### baggage_flag 값

```text

null             : 이슈 없음
```

## 8.4 응답 처리 파이프라인

```text
1. 서버가 AI API 호출 (JSON 응답 강제)
2. 응답 파싱 — 코드펜스 제거 후 JSON.parse
3. 스키마 검증 (zod) — 필수 필드, 카테고리 1개 이상, 항목 3개 이상
4. 검증 실패 시 1회 자동 재시도 (재시도 프롬프트에 실패 사유 포함)
5. 재시도도 실패하면 오류 안내 + [다시 시도] 버튼
6. 성공 시: 로그인 사용자는 DB 저장 후 반환, 비로그인은 그대로 반환
```

---

## 8.5 비용·품질 관리

```text
- 리스트 생성 1회 = AI 호출 1회 (리스트 + 주의사항 + 규정 요약을 한 번에 생성)
- 동일 입력(목적지+목적+월) 캐싱: 서버 캐시 24시간 — 단, 사용자별 편집본은 캐시와 무관
- max_tokens 상한 설정으로 폭주 방지
- 비로그인 사용자 생성 횟수 제한: IP당 하루 5회 (남용 방지)
- 로그인 사용자: 하루 20회
```

## 9. 수화물 체커 판정 로직 상세

## 9.1 판정 우선순위

```text
1단계: 정규화 — 입력 제품명을 소문자/동의어 처리 ("샴푸", "shampoo", "샴푸통" → shampoo)
2단계: 규칙 DB 매칭 — 매칭되면 DB 기준으로 즉시 판정 (AI 호출 없음)
3단계: DB 미스 시 AI 판정 — "AI 판정" 라벨과 함께 결과 표시
4단계: AI 판정 결과 중 빈도 높은 품목은 검수 후 규칙 DB에 편입 (운영 루프)
```

정확성이 중요한 기능이므로 **자주 검색되는 품목일수록 규칙 DB로 수렴**시키는 구조를 만든다.

---

## 9.2 규칙 DB 초기 구축 범위

국토교통부 항공보안 고시 + IATA 기준으로 초기 40~60개 품목을 구축한다.

### 카테고리 예시

```text
액체/젤류: 화장품, 선크림, 향수, 치약, 샴푸, 음료, 김치/장류
배터리: 보조배터리(Wh 구간별), 노트북, 카메라 예비 배터리, 전동휠
인화성: 라이터, 성냥, 부탄가스, 헤어스프레이, 알코올(도수 구간별)
날카로운 물건: 손톱깎이, 가위, 면도기, 맥가이버칼, 등산 스틱
의약품/식품: 상비약, 처방약, 이유식, 분유, 즉석밥
스포츠 장비: 스키, 골프백, 서핑보드, 자전거, 다이빙 장비
기타: 전자담배, 드론, 우산, 셀카봉, 임신테스트기
```

---

## 9.3 규칙 판정 조건식 예시

```text
품목: 보조배터리
단위: Wh (mAh 입력 시 3.7V 기준 환산: Wh = mAh × 3.7 / 1000)

Wh ≤ 100        → 기내 ○ / 위탁 ✕
100 < Wh ≤ 160  → 기내 △ (항공사 승인, 최대 2개) / 위탁 ✕
Wh > 160        → 기내 ✕ / 위탁 ✕
```


## 16. 예외 상황

## 16.1 AI 호출 실패

```text
타임아웃/5xx: 1회 자동 재시도 → 실패 시 오류 안내 + [다시 시도]
스키마 검증 실패: 실패 사유 포함 재요청 1회 → 실패 시 오류 안내
레이트리밋 초과: "오늘 생성 가능 횟수를 모두 사용했어요" + 로그인/내일 안내
```

표시 문구:

```text
리스트 생성에 실패했어요. 잠시 후 다시 시도해주세요.
```

## 16.2 AI 정보 부정확성 (환각) 대응

* 시의성 정보(비자, 환율, 입국 서류)는 `confidence: check_required`로 받아 UI에서 "출발 전 확인" 뱃지를 붙인다.
* 수화물 판정은 자주 검색되는 품목을 규칙 DB로 수렴시켜 AI 의존도를 낮춘다.
* 모든 규정성 정보에 고지 문구를 고정 노출한다. (7.6 고지 문구)
* 결과 카드에 [오류 신고] 버튼을 두어 잘못된 판정을 수집한다.

## 16.3 모호한 입력

```text
목적지 불명확 ("바다", "따뜻한 곳"): 일반 기준 생성 + 구체 입력 유도 문구
체커에 규정과 무관한 입력 ("행복"): "수화물 품목을 입력해주세요" 안내
용량 없이 액체류 검색: 용량별 기준을 모두 표시 ("100ml 이하면 기내 가능…")
```

## 17. 보안 및 개인정보

```text
- AI API 키, DB 접속 정보는 서버 환경변수로만 관리
- 비밀번호는 bcrypt 해시 저장, 평문 로그 금지

- 비로그인 데이터는 서버에 저장하지 않음 (로컬 한정)
- AI 프롬프트에 이메일 등 개인정보를 포함하지 않음
```

## 21. 최종 제품 방향

챙김은 단순히 준비물 목록을 뽑아주는 서비스가 아니다.

기존 체크리스트 앱이 답하는 질문은 다음과 같다.

```text
여행 갈 때 보통 뭘 챙기지?
```

챙김이 답하는 질문은 다르다.

```text
"이번" 여행에는 뭘 챙겨야 하고, 뭘 조심해야 하고, 뭘 들고 탈 수 있지?
```

핵심은 AI가 만든 리스트를 사용자가 소유하게 만드는 것이다. AI는 시작점을 제공하고, 편집·체크·메모를 통해 리스트는 사용자의 것이 된다. 저장된 여행은 다음 여행의 자산이 되고, 수화물 체커는 여행이 없을 때도 재방문할 이유를 만든다.

초기 버전은 목적지·목적 입력 → AI 리스트 + 주의사항 + 규정 요약, 그리고 수화물 체커로 시작한다. 이후 협업 편집, 리마인더, 날씨 연동을 결합하면 "여행 전 단계"를 온전히 담당하는 준비 플랫폼으로 확장할 수 있다.
